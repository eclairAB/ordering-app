# Local Ordering System

Customers order from their phones over the shop LAN; staff see orders live on a kitchen screen. Runs entirely offline on one small box. See [CLAUDE.md](CLAUDE.md) for the rules and architecture.

## First run

```sh
pnpm install
cp .env.example .env        # then set STAFF_PASSCODE and SHOP_TIMEZONE
pnpm db:seed                # demo menu + placeholder images (data/ is gitignored)
pnpm dev
```

| What | Dev URL |
| --- | --- |
| Customer app | http://localhost:5173 (and `http://<this-machine's-LAN-IP>:5173` from a phone) |
| Staff app (kitchen + menu) | http://localhost:5174/staff/ |
| API server | http://localhost:3000 (`/healthz`, `/api/...`) |

Log in to the staff app with `STAFF_PASSCODE` (default `change-me`).

## Production-style run (single process)

```sh
pnpm build                  # builds both apps into apps/*/dist
NODE_ENV=production pnpm start
```

Outside `NODE_ENV=development` the server refuses to start unless `STAFF_PASSCODE` is set to at least 8 characters and isn't `change-me`; anyone on the customer Wi-Fi can reach the staff login. It then serves the customer app at `/`, the staff app at `/staff/`, menu images at `/images/`, and the API at `/api/`.

## Useful commands

- `pnpm test`, `pnpm lint`, `pnpm typecheck`: must pass before committing
- `pnpm db:migrate`: apply migrations (the server also does this on start)
- `pnpm db:seed --reset`: wipe **menu and orders**, then reseed the demo data

## Notes

- Use `pnpm`, not `npm`; npm can't read pnpm's `node_modules` layout.
- Menu images are SVG placeholders generated by the seed script into `data/images/menu/`. Replace a file there (or point `image_path` at a new one) to use a real photo.
- Requires Node 22.18+ (the server runs TypeScript directly via Node's type stripping).
